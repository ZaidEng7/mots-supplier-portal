## 1. Conventions (apply to every table unless noted)

| Concern | Decision | Rationale |
|---|---|---|
| **Schema layout** | Logical schemas: `identity`, `supplier`, `rfq`, `proposal`, `evaluation`, `award`, `shared`, `reference`, `ops` (outbox/audit/jobs). | Bounded-context grouping; simpler grants and search_path scoping. |
| **Primary key** | `id uuid PRIMARY KEY` — **GUIDv7**, generated by the app (`Guid.CreateVersion7()`), not `gen_random_uuid()`. | Time-ordered → sequential B-tree inserts, no page-split amplification; minted pre-insert for Outbox atomicity (DOMAIN-MODEL §2.1). |
| **Naming** | `snake_case`, singular table names, plural only for join tables where natural. FKs `<referenced>_id`. | Postgres-idiomatic, EF Core mapped via naming convention. |
| **Timestamps** | `timestamptz` (UTC) everywhere; never `timestamp`. | Correct across locales/DST; app formats per user locale (foundational §8). |
| **Money** | `numeric(18,4)` amount + `char(3)` ISO-4217 `currency_code`. **No `float` for money.** | Exact decimal; multi-currency proposals (foundational §8). |
| **Text** | `text` (not `varchar(n)`) with `CHECK (char_length(...) <= N)` where a bound is meaningful. | Postgres `text` has no perf penalty; checks stay explicit. |
| **Localized text** | Paired `*_ar text` + `*_en text` columns (Arabic NOT NULL, English nullable) **or** a `jsonb` `{ar,en}` for large sets. | Arabic-first (foundational §8). |
| **Auditing columns** | `created_at timestamptz NOT NULL`, `created_by uuid`, `modified_at timestamptz`, `modified_by uuid`. Set by EF `SaveChanges` interceptor. | Uniform provenance; distinct from the full AuditLog. |
| **Concurrency** | `row_version` — Postgres system column **`xmin`** mapped as EF concurrency token (no extra column). | Optimistic concurrency at the aggregate root, zero storage cost (§8). |
| **Soft delete** | **Opt-in only** via `is_deleted boolean NOT NULL DEFAULT false` + `deleted_at`, `deleted_by`. Applied to a **short justified list** (§9); everything else is **hard delete + AuditLog**. | Foundational §9 — soft-delete only where lifecycle demands. |
| **Enums** | Native **PG enum** for small, stable, code-owned sets (states, statuses). **Lookup table** for business-editable/reference sets. | §7 decision matrix. |
| **JSONB** | Flexible offering attributes, event payloads, criterion snapshots, notification data. `jsonb` + GIN where queried. | Foundational §2 "JSONB for flexible offerings". |
| **FK actions** | `ON DELETE RESTRICT` by default; `CASCADE` only **within an aggregate** (root → owned children). | Aggregate integrity (DOMAIN-MODEL §8). |
| **Extensions** | `pgcrypto` (hashing), `pg_trgm` (Arabic/Latin fuzzy search), `citext` (case-insensitive email). | Search + identity ergonomics. |

### 1.1 ERP sync columns (only on syncable aggregate roots)

Applied to `supplier.supplier`, `rfq.rfq`, `proposal.proposal`, `award.award`,
`identity.organization` (foundational §4, DOMAIN-MODEL §2.3):

```
external_id       text        NULL      -- ERPNext naming-series key, e.g. 'SUP-2026-00078'
sync_status       sync_status NOT NULL DEFAULT 'not_applicable'  -- PG enum
last_synced_at    timestamptz NULL
last_sync_error   text        NULL
```
Constraint: `UNIQUE (external_id) WHERE external_id IS NOT NULL` (partial unique — one portal row per
ERP key, nulls unconstrained). **Never** an integer FK to ERP (Discovery §3.2.1).

### 1.2 Reference-code allocation

Public codes (`RFQ-2026-000123`, DOMAIN-MODEL §2.2) are allocated from a per-prefix, per-year counter
to avoid gaps and races:

```
reference.code_sequence (
    prefix     char(3)  NOT NULL,   -- 'RFQ','PRO','SUP','AWD',...
    year       smallint NOT NULL,
    next_value bigint   NOT NULL DEFAULT 1,
    PRIMARY KEY (prefix, year)
)
```
Allocation uses `INSERT ... ON CONFLICT (prefix,year) DO UPDATE SET next_value = code_sequence.next_value + 1 RETURNING next_value`
(atomic, contention-safe). The formatted code is stored on the row as `reference_code text NOT NULL`
with a `UNIQUE` index.

## 4. Outbox table design {#outbox-table}

The transactional Outbox (foundational §2, §5; DOMAIN-MODEL §7) guarantees domain/integration events
are persisted **atomically** with the state change that produced them, then relayed (in-process
handlers + ERP ACL) with durable retry via Hangfire.

```sql
CREATE TABLE ops.outbox_message (
    id               uuid        PRIMARY KEY,              -- GUIDv7, minted in the same UoW
    occurred_at      timestamptz NOT NULL,
    aggregate_type   text        NOT NULL,                 -- 'Supplier','RFQ','Award',...
    aggregate_id     uuid        NOT NULL,                 -- source aggregate root
    event_type       text        NOT NULL,                 -- 'SupplierApproved','AwardFinalized',...
    payload          jsonb       NOT NULL,                 -- serialized event (versioned schema)
    schema_version   smallint    NOT NULL DEFAULT 1,
    correlation_id   uuid        NOT NULL,                 -- threads command → event → audit → logs
    causation_id     uuid        NULL,                     -- event that caused this event
    destination      text        NOT NULL DEFAULT 'internal', -- 'internal' | 'erp'
    status           outbox_status NOT NULL DEFAULT 'pending', -- pending|processing|processed|failed|dead
    attempt_count    smallint    NOT NULL DEFAULT 0,
    next_attempt_at  timestamptz NOT NULL DEFAULT now(),
    processed_at     timestamptz NULL,
    last_error       text        NULL,
    available_lock   uuid        NULL                      -- worker claim token (SKIP LOCKED)
);

-- Dispatcher poll: only unprocessed, due rows, oldest first, claimed with SKIP LOCKED.
CREATE INDEX ix_outbox_dispatch
    ON ops.outbox_message (next_attempt_at)
    WHERE status IN ('pending','failed');

CREATE INDEX ix_outbox_correlation ON ops.outbox_message (correlation_id);
```

Semantics:

- **Write path:** the domain command handler saves aggregate changes **and** the outbox row in one EF
  Core transaction. If the transaction commits, the event will eventually be delivered; if it rolls
  back, no event exists — no dual-write inconsistency.
- **Relay:** a Hangfire recurring worker selects due rows `FOR UPDATE SKIP LOCKED`, dispatches to
  in-process handlers and/or the ERP ACL adapter, and marks `processed`/`failed` with exponential
  `next_attempt_at` backoff. After max attempts → `dead` (dead-letter, alerting).
- **Idempotency:** consumers (esp. the ERP ACL) key on `id` so a redelivery is a no-op — enabling
  effectively-exactly-once (foundational §5).
- **Retention:** `processed` rows pruned by a scheduled job after a retention window; **partition
  candidate** by `occurred_at` month at scale (§10).

## 5. Audit table design {#audit-table}

Every state change records an **immutable** audit entry in the same unit of work (foundational §5, §9;
DOMAIN-MODEL §5.9). This is the compliance record; it is append-only and `audit.read`-gated.

```sql
CREATE TABLE ops.audit_log (
    id             uuid        PRIMARY KEY,               -- GUIDv7 (time-ordered)
    occurred_at    timestamptz NOT NULL,
    actor_user_id  uuid        NULL,                      -- null for system/job actors
    actor_kind     audit_actor_kind NOT NULL,            -- user | system | integration
    actor_label    text        NULL,                      -- denormalized display (survives user delete)
    aggregate_type text        NOT NULL,                  -- 'Supplier','RFQ','Proposal',...
    aggregate_id   uuid        NOT NULL,
    reference_code text        NULL,                      -- e.g. 'RFQ-2026-000123'
    action         text        NOT NULL,                  -- 'state_change','update','approve','reject'...
    from_state     text        NULL,                      -- transition source (state machines)
    to_state       text        NULL,                      -- transition target
    reason         text        NULL,                      -- mandatory for reject/cancel/override
    changes        jsonb       NULL,                      -- field-level before/after (redacted for PII)
    correlation_id uuid        NOT NULL,                  -- ties to outbox + logs
    ip_address     inet        NULL,
    user_agent     text        NULL
);

CREATE INDEX ix_audit_aggregate ON ops.audit_log (aggregate_type, aggregate_id, occurred_at DESC);
CREATE INDEX ix_audit_actor     ON ops.audit_log (actor_user_id, occurred_at DESC);
CREATE INDEX ix_audit_correlation ON ops.audit_log (correlation_id);
```

Guarantees & policy:

- **Append-only.** No `UPDATE`/`DELETE` from application code; enforced by a restricted DB role
  (grant `INSERT, SELECT` only) and, defensively, a rule/trigger blocking mutation.
- **Denormalized actor label** so audit stays legible even after a user is hard-deleted (audit
  outlives the actor — key reason we can hard-delete users, §9).
- **`reason` is mandatory** for every reject/cancel/override transition (foundational §5).
- **`changes`** stores a redacted field-level diff (secrets/PII masked before persistence).
- **Partition candidate** by `occurred_at` range (monthly) — see §10; a high-volume append-only table.

## 6. JSONB usage — flexible offerings & snapshots {#offering-jsonb}

JSONB is used deliberately, **not** as a schema escape hatch. Structured, queried, relationally-shaped
data stays in columns; genuinely variable or point-in-time-frozen data uses JSONB.

| Column | Shape | Why JSONB | Query strategy |
|---|---|---|---|
| `supplier.offering.attributes` | category-specific key/values (e.g. hotel-linen `{material, gsm, sizes[]}` vs transport `{fleet_type, capacity}`) | Attributes vary per category; forcing columns would explode the schema (foundational §2 "JSONB for flexible offerings"). | **GIN**`(attributes jsonb_path_ops)`; queried via `@>` containment; a per-category JSON Schema validates writes in the app layer. |
| `rfq.evaluation_template_snapshot` | frozen copy of criteria + weights at RFQ approval | Must be **immutable** even if the source template later changes (DOMAIN-MODEL §5.4). | Read-only; not indexed (accessed by RFQ id). |
| `proposal.technical_response` | answers to requirements + narrative | Requirement set is per-RFQ and variable. | Read with proposal; occasional GIN if reporting needs it. |
| `consolidated_result.breakdown` | per-criterion contribution to weighted total | Derived, display-oriented, variable width. | Read-only. |
| `ops.outbox_message.payload`, `ops.audit_log.changes`, `notification.data` | event/diff/notification bodies | Heterogeneous per event type; versioned by `schema_version`. | Rarely queried into; occasional GIN for support tooling. |

Rule of thumb enforced in review: **anything filtered, joined, aggregated, or FK'd stays a column.**

## 7. Enums vs lookup tables {#enum-decision}

| Use **native PG enum** when… | Use a **lookup table** when… |
|---|---|
| The set is small, stable, and **owned by code** (the domain's own state machines). | The set is business-editable, extensible at runtime, or carries extra attributes. |
| Values map 1:1 to a C# enum and drive `switch`/guards. | Rows need `name_ar/_en`, `is_active`, ordering, or FK targets. |

**Native enums (code-owned state machines, foundational §5):**
`sync_status`, `supplier_onboarding_state`, `supplier_lifecycle_state`, `supplier_document_state`,
`supplier_type`, `rfq_state`, `invitation_status`, `clarification_visibility`, `proposal_state`,
`evaluation_state`, `evaluator_state`, `evaluation_template_status`, `criterion_dimension`,
`scoring_type`, `evaluation_aggregation`, `award_state`, `approval_decision`, `organization_type`,
`outbox_status`, `audit_actor_kind`, `notification_channel`, `notification_delivery_status`,
`document_scan_status`.

> **Migration note:** PG enums add values with `ALTER TYPE ... ADD VALUE` (non-transactional pre-PG12
> caveat resolved in 17) but cannot easily reorder/remove; if a "state" ever needs business editing it
> is promoted to a lookup table. State machines are code-owned by design, so enums are the right fit.

**Lookup tables (business/reference data, §2.9):** `category`, `document_type`, `currency`,
`unit_of_measure`, `incoterm`, `region`, `role`, `permission`.

## 8. Concurrency control {#concurrency}

- **Optimistic concurrency at the aggregate root** using Postgres system column **`xmin`** mapped as
  an EF Core concurrency token (`.IsRowVersion()` via Npgsql). No dedicated `row_version` column is
  stored — `xmin` changes on every row update automatically.
- On `SaveChanges`, EF issues `UPDATE ... WHERE id = @id AND xmin = @original_xmin`; zero rows affected
  → `DbUpdateConcurrencyException` → the command handler returns a `409 Conflict` with a
  reload-and-retry hint. This protects whole aggregates against lost updates (DOMAIN-MODEL §8).
- **Reference-code and sequence allocation** avoid lost updates via the atomic `INSERT ... ON CONFLICT
  ... DO UPDATE ... RETURNING` upsert (§1.2), not read-modify-write.
- **Outbox claiming** uses `SELECT ... FOR UPDATE SKIP LOCKED` so multiple relay workers never process
  the same row.
- **State transitions** are guarded in-domain; combined with `xmin`, two officers cannot both publish
  the same RFQ — the second commit fails the concurrency check.

## 9. Soft-delete policy {#soft-delete}

**Default is hard delete + AuditLog** (foundational §9). Soft delete (`is_deleted`, `deleted_at`,
`deleted_by` + a global EF query filter) is applied **only** where lifecycle/compliance demands
recoverability or where dependent history must not dangle:

| Table | Delete policy | Justification |
|---|---|---|
| `supplier.supplier` | **Soft** | Regulated party master with downstream RFQ/proposal history; must remain referenceable; ERP-synced. |
| `rfq.rfq` | **Soft** | Procurement record of record; proposals/awards reference it; legal retention. |
| `proposal.proposal` | **Soft** | Bid evidence for audit/dispute; referenced by evaluation/award. |
| `award.award` | **Soft** | Contractual outcome; drives ERP PO; never truly deleted. |
| `shared.document` | **Soft** | Referenced by multiple owners; content-hash dedupe; retained per policy. |
| `identity.app_user` | **Hard** (deactivate first) | AuditLog denormalizes actor label (§5), so history survives deletion; PII minimization favors true removal on lawful request. |
| `evaluation.evaluator_score` | **Hard** (pre-finalize) | Draft scores; after `Finalized` the consolidated result is the retained record. |
| Drafts (`rfq`/`proposal` in `Draft`) | **Hard** allowed | Never-published working data; no downstream references. |
| Reference/lookup, join tables, `outbox`, notifications | **Hard** (+ audit / retention job) | No lifecycle need; kept lean. |

A soft-deleted row is excluded by the EF global filter, retains its `UNIQUE(reference_code)`, and its
deletion is itself an AuditLog entry.

## 10. Partitioning candidates {#partitioning}

Introduced when volume warrants (not premature); all are append-heavy, time-ordered, and rarely
updated:

| Table | Strategy | Trigger |
|---|---|---|
| `ops.audit_log` | **Range** partition by `occurred_at` (monthly), detach-and-archive old partitions. | Highest write volume; every state change writes here. |
| `ops.outbox_message` | **Range** by `occurred_at` (monthly); processed partitions pruned. | High churn; keeps the hot `pending/failed` index small. |
| `shared.notification` | **Range** by `created_at` (monthly). | Grows with user activity; read-recent pattern. |
| `identity.user_session` | **Range** by `expires_at`, or periodic purge job. | Session churn; expired rows purged. |
| `evaluation.evaluator_score` | Not partitioned (bounded per RFQ); indexed only. | Bounded cardinality. |

Partition keys are chosen to align with query predicates (time-range dashboards, retention jobs) so
partition pruning is effective. GUIDv7 PKs remain globally unique across partitions.

## 11. Indexing & performance summary

Aligned to NFR targets (foundational §9: reads p95 < 300ms, writes p95 < 800ms):

- **Row-scoping indexes** on every scoped table: `supplier_id` / `organization_id` composited with the
  common `state` predicate (e.g. `proposal(supplier_id, state)`, `rfq(organization_id, state)`), since
  RBAC always filters by scope first (foundational §6).
- **Partial indexes** for sweeps and one-of constraints: `supplier_document(expires_on) WHERE ...`,
  `representative(supplier_id) WHERE is_primary`, `outbox(next_attempt_at) WHERE status IN (...)`.
- **Trigram (`pg_trgm`) GIN** on Arabic + English display names for typeahead/search under both locales.
- **JSONB GIN** (`jsonb_path_ops`) only on `offering.attributes` where containment search is a real
  query path (§6).
- **Covering/uniqueness**: business uniqueness enforced in-DB (`proposal(rfq_id, supplier_id)`,
  `invitation(rfq_id, supplier_id)`, partial `unique(external_id)`), never left to app-only checks.
- **`citext`** on `app_user.email` for case-insensitive uniqueness without functional-index overhead.
